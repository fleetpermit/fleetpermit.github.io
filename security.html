Security model

With the default-deny anchor installed, errors never add authority: a failure withdraws grants or leaves them to expire on time. This page shows how that works, and where it stops.

Trust boundaries

The hub makes decisions but does not sit in the request path. Kubernetes RBAC on the hub decides who may write a FleetAccessPolicy (the ceiling) and who may create a ToolAccessLease (activation), so on-call engineers can activate access without being able to change the ceiling. FleetPermit never issues, stores or sees credentials. The gateway authenticates the caller from its mTLS peer certificate.

The controller has no access to the Secret, workload or RBAC APIs on the hub. Its ManifestWork permissions cover every managed-cluster namespace, though: it can read every ManifestWork on the hub, including content other tools deliver, which can embed Secrets, and it can create and update ManifestWork that the OCM work agent applies on the managed cluster. Treat the controller's ServiceAccount as a privileged credential.

The --work-executor flag makes the OCM work agent check FleetPermit's content against a restricted managed-cluster ServiceAccount before applying it. The agent still writes with its own identity, and the lab tests do not exercise this option. It does not stop a stolen controller credential on its own: that credential can create a ManifestWork without an executor, which the work agent applies with its own permissions. Only OCM's NilExecutorValidating feature gate on the hub, which is alpha and off by default, makes OCM check those too.

On each managed cluster, work-agent-rbac.yaml adds XAccessPolicy permissions to the OCM work agent; it does not restrict the agent.

Principles

  1. Ceiling and activation are separate objects

    A FleetAccessPolicy defines the maximum. A ToolAccessLease activates part of it for a bounded time.

  2. Enforce where the call happens

    Identity, tool and time are all checked by the gateway in front of the tool server.

  3. With the default-deny anchor installed, errors never add authority

    No placement means nothing is delivered, and existing grants are withdrawn. A render error withdraws that cluster's grants. A lease that violates its policy is Denied, and Denied is terminal. With the hub or the controller down, delivered leases still expire on time. failMode accepts only Closed. On a cluster that FleetPermit does not currently select, or has withdrawn from, the backend is closed only when the anchor is installed; on selected clusters FleetPermit's inert policy also denies. Upstream enforces nothing on a backend without any XAccessPolicy.

  4. Subset only

    A lease can narrow tools, duration and clusters, never widen them, and its spec cannot be edited after creation.

  5. Traceable

    Every delivered object carries the source policy and its UID, the cluster and a SHA-256 content digest. Objects with lease grants also list the lease UIDs and the latest expiry, so a rule found on a cluster leads back to the request that created it.

Limits

  • XAccessPolicy (v1alpha1) and XBackend (v0alpha0) in kube-agentic-networking are experimental. Upstream marks its reference implementation as not production-ready.
  • kube-agentic-networking v0.2.0 matches the tool name only. A call such as scale_workload with replicas=1000 cannot be refused by argument.
  • Upstream allows at most 5 XAccessPolicies per target and 10 rules per policy, so about 9 concurrent lease grants fit per policy per cluster. Excess leases are reported as CapacityExceeded, and a lease that fits on no cluster waits in Pending.
  • The MCP base protocol methods (initialize, tools/list, ping, completion/*, logging/*, notifications/*, the event stream and session close) are allowed by a separate rule that has no time bound in the data plane; the controller removes it. They cannot call tools.
  • kube-agentic-networking v0.2.0 combines the Allow policies on a target with OR, while its API documentation says all of them must allow a request. The default-deny anchor depends on the implemented behaviour, so FleetPermit tracks it with every upstream upgrade.
  • Expiry uses each managed cluster's clock. A clock that runs behind honours a grant for longer, by the amount of skew.
  • Deleting a lease before it expires reaches only clusters the hub can contact, so early revocation needs the hub. Keep lease durations short.
  • All measurements come from local kind clusters on one development host, except the GitHub-hosted reproduction and the envtest scale simulation. They are not a production benchmark.

FleetPermit does not make tool calls safe, does not guarantee the absence of vulnerabilities, and does not replace RBAC, network policy or authorization inside the tool server. It narrows who can call which tool, where, and for how long, and it reports what it enforces.

Reporting a vulnerability

Please do not open a public issue. Use GitHub private vulnerability reporting on the repository: report a vulnerability. Only maintainers can see the report. See the security policy summary.
