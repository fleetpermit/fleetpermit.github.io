Contributing

Start with CONTRIBUTING.md and the code of conduct. A few ground rules:

  • Open an issue first for API changes, security-model changes or new dependencies.
  • New direct dependencies must come from the Kubernetes, CNCF or Linux Foundation ecosystems and be recorded in DEPENDENCIES.md.
  • Add tests at the lowest layer that proves the behaviour: unit tests for pure logic, test/integration for anything involving the API server, and a scenario in test/e2e/run.sh for anything that needs real gateways or OCM.
  • Documentation that states a behaviour or a number points to a test or a measurement.
before you open a pull request
$ make verify    # every static check CI runs
$ make test      # unit and integration tests
$ make generate  # after changing api/ or an RBAC marker

Good first contributions: documentation fixes, new troubleshooting entries, and tests that pin down upstream behaviour FleetPermit relies on. Browse open issues.

Governance

FleetPermit is an independent open-source project. It is not part of, or endorsed by, the CNCF, the Linux Foundation or the Kubernetes project, although it builds on their technologies.

  • Contributors open issues, review and submit pull requests.
  • Maintainers review and merge changes, triage issues, cut releases and handle security reports.
  • Decisions happen in pull requests by lazy consensus. Changes to the API, the security model or the dependency policy need an issue or design document first and approval from a majority of maintainers.
  • New maintainers are nominated by a maintainer after sustained contributions and approved by a majority. The project aims for maintainers from more than one organisation as it grows.

Three principles every change must respect: vendor neutrality, errors that never add authority (with the default-deny anchor installed), and claims backed by tests or measurements. Read the full GOVERNANCE.md.

Security reporting

Please do not open a public issue for a security problem.

Report it privately with GitHub private vulnerability reporting: open the repository's Security tab and choose Report a vulnerability, or use the direct link. Only the maintainers can see the report.

Include the affected version or commit, the issue and its impact, and steps to reproduce. A failing test or a lab scenario is ideal. Expect an acknowledgement within 5 business days and an assessment within 30 days, followed by coordinated disclosure through a GitHub Security Advisory.

Vulnerabilities in upstream projects such as Open Cluster Management, kube-agentic-networking, Envoy or Kubernetes belong with those projects. Tell FleetPermit as well if its use of them makes an issue exploitable. Full policy: SECURITY.md.

Roadmap

v0.1 supports one placement provider (Open Cluster Management), one enforcement provider (kube-agentic-networking) and one protocol (MCP). The first list shows what it includes. The enhancements below follow user feedback and upstream progress.

In v0.1

  • DoneFleetAccessPolicy and ToolAccessLease APIs (v1alpha1) with strict validation
  • DoneOpen Cluster Management placement and delivery with Placement, PlacementDecision and ManifestWork
  • Donekube-agentic-networking XAccessPolicy enforcement, with the lease expiry enforced in the data plane
  • DoneDefault-deny anchor for tool backends; drift detection and immediate re-apply requests
  • DonePer-cluster status, Prometheus metrics and OpenTelemetry traces
  • DoneHelm chart, reproducible 1 hub + 3 cluster lab, end-to-end scenarios and benchmarks
  • DoneSigned container images and release assets, with an SPDX SBOM per release

Enhancements under consideration

  • NextArgument-level MCP matching, such as limits on replicas, and native expiry, when upstream supports them
  • NextFaster detection of in-place edits to delivered objects
  • NextGuidance and tests for federated SPIFFE trust domains across clusters
  • NextBuild provenance attestations, and the Helm chart as an OCI artifact
  • LaterAdditional placement and enforcement providers from neutral projects, through the existing seams
  • LaterAn optional approval workflow for leases

See ROADMAP.md for the current list and what is out of scope.
