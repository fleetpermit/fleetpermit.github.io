Prerequisites

For the local lab

  • Go (the version in go.mod), Helm and Python 3
  • podman, or docker when podman is absent. With podman the scripts set KIND_EXPERIMENTAL_PROVIDER=podman.
  • kind, kubectl, clusteradm, jq and curl
  • About 8 CPUs and 16 GiB of memory for four kind clusters

For a real fleet

Requirements on the hub and managed clusters
WhereWhat
HubKubernetes with the Open Cluster Management hub (v1.3 tested): Placement, PlacementDecision and ManifestWork APIs. Tested on Kubernetes 1.35; the chart accepts 1.30 and later, which is untested.
Each governed managed clusterOCM klusterlet; Gateway API; kube-agentic-networking (v0.2.0 tested) with a Gateway; the tool server as an XBackend; workload identities the gateway trusts.

Lab quick start

The lab creates one hub and three managed kind clusters: cluster-east and cluster-west labelled env=production, and cluster-edge labelled env=staging. It uses its own kubeconfig and never touches your current context.

terminal
$ git clone https://github.com/fleetpermit/fleetpermit
$ cd fleetpermit
$ make demo-up      # create the lab and install everything
$ make demo-run     # narrated authorization demo
$ make test         # unit and integration tests (no lab needed)
$ make test-e2e     # multi-cluster end-to-end scenarios
$ make benchmark    # latency and simulated controller scale
$ make demo-down    # delete only the clusters this lab created

Install on a real fleet

Install the controller on the OCM hub:

on the OCM hub
$ helm install fleetpermit charts/fleetpermit -n fleetpermit-system --create-namespace

Then, on every managed cluster that runs a governed tool server, add XAccessPolicy permissions to the OCM work agent and close the backend by default:

on each managed cluster
$ kubectl apply -f config/managed-cluster/work-agent-rbac.yaml
$ kubectl apply -f config/managed-cluster/default-deny-anchor.yaml
Install the anchor on every cluster that runs the backend.

That includes clusters no placement selects today. Upstream enforces nothing on a target with no XAccessPolicy, so without the anchor the backend is open. Edit the namespace and backend name in default-deny-anchor.yaml to match your tool server.

Your first lease

A Placement only selects clusters from a ManagedClusterSet that is bound to its namespace, and this one selects clusters labelled env=production. Set that up first, as the lab does in demo/scripts/lab-up.sh: add each managed cluster to the fleet set and label the ones the policy should reach.

on the hub
$ kubectl label managedcluster cluster-east cluster.open-cluster-management.io/clusterset=fleet env=production
$ kubectl label managedcluster cluster-west cluster.open-cluster-management.io/clusterset=fleet env=production
$ kubectl label managedcluster cluster-edge cluster.open-cluster-management.io/clusterset=fleet env=staging
$ kubectl create namespace fleet
$ kubectl apply -f clusterset.yaml
clusterset.yaml
apiVersion: cluster.open-cluster-management.io/v1beta2
kind: ManagedClusterSet
metadata:
  name: fleet
spec:
  clusterSelector:
    selectorType: ExclusiveClusterSetLabel
---
apiVersion: cluster.open-cluster-management.io/v1beta2
kind: ManagedClusterSetBinding
metadata:
  name: fleet
  namespace: fleet
spec:
  clusterSet: fleet

Then create the Placement, the policy that references it, and a lease. All three live in the fleet namespace on the hub.

placement.yaml
apiVersion: cluster.open-cluster-management.io/v1beta1
kind: Placement
metadata:
  name: production-clusters
  namespace: fleet
spec:
  clusterSets: [fleet]
  predicates:
    - requiredClusterSelector:
        labelSelector:
          matchLabels:
            env: production

Use the FleetAccessPolicy and ToolAccessLease from the 30-second example, then watch them:

kubectl output
$ kubectl get fleetaccesspolicy -n fleet
NAME              CLUSTERS   READY   ACTIVE-LEASES   AGE
sre-remediation   2/2        True    1               10m

$ kubectl get toolaccesslease -n fleet
NAME          POLICY            CLUSTERS   EXPIRES-AT             STATUS   AGE
incident-42   sre-remediation   2          2026-09-26T10:15:00Z   Active   1m

Short names work too: kubectl get fap,tal -n fleet. Add -o wide to the lease to see its subject.

API reference

API group fleetpermit.github.io, version v1alpha1. Both kinds are namespaced: a lease references a policy in its own namespace, and a policy references an OCM Placement in its own namespace.

Validation happens in two places. The API server enforces the OpenAPI schema and CEL rules: field patterns and lengths, list sizes and uniqueness, enums, duration limits and lease immutability. The controller checks what depends on another object when it evaluates a lease: the policy exists, the subject is in the policy, the tools are a subset of its permissions, the duration is at most maxDuration, and the requested clusters are placed. A lease that fails a controller check is stored and marked Denied, or Pending for the placement check. The tables say which side enforces each rule.

FleetAccessPolicy (short name fap)

The ceiling: the most authority any lease may activate.

FleetAccessPolicy spec fields
FieldDefaultMeaning and validation
spec.subjects[].spiffeIDrequiredAPI server: 1 to 16 unique SPIFFE IDs, pattern ^spiffe://[a-z0-9._-]+(/[A-Za-z0-9._-]+)*$
spec.placement.providerocmAPI server: only ocm
spec.placement.placementRef.namerequiredAn OCM Placement in the same namespace. Controller: PlacementNotFound if it is missing
spec.target.protocolMCPAPI server: only MCP
spec.target.namespacerequiredNamespace of the target on each managed cluster. API server: a DNS label
spec.target.ref.kindXBackendAPI server: XBackend or Gateway
spec.target.ref.groupagentic.networking.x-k8s.ioAPI server: or gateway.networking.k8s.io
spec.target.ref.namerequiredThe backend or gateway name
spec.permissions[].toolrequiredAPI server: 1 to 16 unique MCP tool names, pattern ^[A-Za-z0-9][A-Za-z0-9_.-]*$, at most 20 characters. Re-checked by the renderer
spec.lease.requiredtruefalse grants every permission to every subject without a lease (standing access)
spec.lease.defaultDuration15mUsed when a lease omits duration. API server: at least 10s, at most maxDuration
spec.lease.maxDuration1hAPI server: at most 24h
spec.enforcement.providerkubernetes-agentic-networkingAPI server: only value
spec.enforcement.failModeClosedAPI server: only value; an open mode is intentionally not offered

Status reports Ready, Progressing and Degraded conditions, clusterSummary such as 2/2, activeLeases, and one entry per selected cluster with its reason and content digest.

ToolAccessLease (short name tal)

Activates a subset of a policy for a bounded time. The spec is immutable: the API server rejects any change after creation.

ToolAccessLease spec fields
FieldDefaultMeaning and validation
spec.policyRef.namerequiredA FleetAccessPolicy in the same namespace. Controller: Denied if it does not exist
spec.subject.spiffeIDrequiredAPI server: SPIFFE ID pattern. Controller: must be one of the policy's subjects
spec.permissions[].toolrequiredAPI server: 1 to 16 unique tools. Controller: must be a subset of the policy's permissions
spec.durationpolicy defaultDurationAPI server: at least 10s. Controller: at most the policy's maxDuration. When omitted, the default at first evaluation is pinned through status.expiresAt
spec.clusters[]all placed clustersAPI server: at most 64 unique names. Controller: narrows the placement; clusters outside it receive nothing
spec.reasonnoneFree text for audit. API server: at most 256 characters
ToolAccessLease status fields
Status fieldMeaning
phasePending (no requested cluster is placed yet, or the rule limit is reached on every cluster), Active, Expired or Denied; a summary of the conditions
expiresAtcreationTimestamp + effective duration. For a lease without spec.duration, that is the policy default in effect at first evaluation, pinned here. Policy changes never extend it
clusters, clusterCountClusters that hold the grant; after expiry or denial, clusters still being revoked
conditionsReady, Progressing, Degraded, Expired, Denied

Condition reasons

Lease condition reasons
ReasonConditionMeaning
LeaseActiveReady=TrueGranted and enforced on every target cluster
RollingOutProgressing=TrueDelivery or acceptance pending on some clusters
NoEligibleClustersReady=FalseNone of the requested clusters is currently placed (phase Pending)
CapacityExceededDegraded=TrueUpstream rule limit reached on the listed clusters. If that is every cluster, the lease is Pending and activates when capacity frees up
ClustersFailedDegraded=TrueApply failed, rejected by enforcement, or cluster unavailable
PolicyNotFoundDenied=TrueThe referenced policy does not exist
SubjectNotAllowedDenied=TrueThe subject is not in the policy
PermissionNotAllowedDenied=TrueA requested tool is not in the policy
DurationExceedsMaximumDenied=TrueThe duration exceeds maxDuration
LeaseExpiredExpired=TruePast expiresAt

Denied and Expired are terminal, provided only the controller can write toolaccessleases/status. A policy change that removes a lease's tool or subject denies it, and a policy change that would allow a previously denied lease does not revive it. Pending is not terminal.

For a lease without spec.duration, the expiry lives in status.expiresAt. Grant write access to toolaccessleases/status to the controller only: a principal that can write lease status could extend such a lease up to the policy's maxDuration, never beyond it.
